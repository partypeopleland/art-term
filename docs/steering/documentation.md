# AI 導向文件規則

文件讓 AI 在接手主題時，直接理解系統如何運作、為何這樣設計，以及哪些條件會改變結果。讀者從 [INDEX](../INDEX.md) 選擇相關主題，讀完即可建立足以討論、判斷與執行的理解。

## 把一個主題解釋完整

開頭直接交代問題與用途，讓讀者知道這份文件回答什麼。接著介紹參與者與關係；元件位置、資料流、生命週期或信任邊界不容易只靠文字理解時，使用 fenced `text` 的 ASCII 圖。圖中標明箭頭代表的動作或資料，再以正文解釋各步如何連起來。

例如連線搬移需要說明三個階段的保護方式，圖可寫成：

```text
Source device                Transfer file              Destination device
local protected data --export/password--> encrypted JSON --import--> local protected data
```

正文接著解釋：來源裝置先解開自己保存的憑證，再用檔案密碼加密；目的裝置用相同密碼解開搬移檔，最後用自己的平台金鑰重新保存。因此目的裝置需要檔案密碼，不需要來源裝置的金鑰。這個解釋讓讀者理解可攜性的原因，詳細流程留在[連線搬移](../refarch/connection-transfer.md)。

術語第一次出現時說明它代表什麼。限制要連到原因與影響，例如「輸入重送可能讓命令執行兩次，因此重連不重播未確認的輸入」。必要的數值、欄位及命令保留精確形式；不要只堆縮寫，或讓一張表代替整個主題的說明。

章節依主題安排。架構可沿資料流解釋，操作文件可沿準備、執行、失敗復原解釋，ADR／BDR 可沿問題、選擇與代價解釋。圖只在有助理解時使用，不要求每篇套相同模板。

給使用者看的 setup 頁只說明必要依賴、選配需求與可直接複製給 AI 的 prompt，不堆安裝指令，也不重寫 Tailscale 等第三方工具的官方安裝教學。prompt 以專案相對路徑引導 AI 讀取操作文件；AI 文件另行寫清環境檢查、安裝與既有服務分流、必要指令、驗證、失敗處理及交付方式。使用者只需知道要準備什麼、怎麼請 AI 協助，以及最後如何使用；執行細節由其 AI 讀取並處理。

## 文件之間如何連接

每個穩定事實有一個主要歸屬。其他頁先提供足夠理解當前段落的說明，再以主題文件連結引導深入；讀者不必跳走才能理解一句話。正文的延伸閱讀連到同樣能獨立解釋主題的文件。

程式碼、外部規格、研究來源與任務證據可放在文末「附錄：實作與參考」，供維護者追溯。正文不以「去看某函式／原始碼」取代說明。可執行命令與設定範例仍放在需要它們的步驟中，因為它們是操作內容。

## 寫作與維護責任

作者在發布前完成必要查證，將確認後的結論寫進正文。行為改變時，同步更新相關文件；讀者需要修改實作時仍可查程式，但理解文件不以重新查證為前提。不確定或尚未實測的部分明確標示，不用來源連結掩蓋缺口。

正文區分目前行為、未實作提案和有日期的歷史證據。ADR 保留決策與理由，BDR 保留使用者問題、產品取捨與驗證門檻。`docs/` 只放 Markdown（`.md`）文件。`report/` 只放以版本命名的更新說明，例如 `0.1.25.md`，用簡短的使用者語言說明新增或修正哪些功能；必要時說明升級注意事項，不寫實作細節、案例代碼、測試數量、清理步驟或逐次執行結果。測試只維護主題性的操作說明與覆蓋清單，機器使用的案例資料放在測試程式旁。單次測試結果可重新執行取得，不建立公開歷史報告或結果 JSON。

只在一個主題值得獨立說明時拆篇，避免重複手冊或每個資料夾都建立入口。搬移文件時同步修正現行連結；歷史 task 原始證據不改寫。shell 範例預設從 repository 根目錄執行，命令路徑不跟著 Markdown 位置移動。

公開範例只用虛構網址與憑證，不放私人部署資訊。未明示要求時不另外產生人類版／HTML 文件；README 保持專案與原始碼入口，完整知識留在主題頁。
